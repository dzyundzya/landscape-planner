# Landscape Planner

Сервис автоматического проектирования городского озеленения по данным DXF.

## Запуск в Docker

Docker Compose запускает PostgreSQL, применяет миграции, затем поднимает API со
встроенным frontend и отдельный worker. Исходные чертежи и результаты сохраняются
в общем volume, доступном API и worker.

Создайте локальный файл настроек и при необходимости добавьте ключ LLM и DSN
Sentry:

```bash
cp .env.example .env
```

Соберите и запустите весь сервис:

```bash
docker compose up --build
```

После успешного запуска доступны:

- интерфейс: `http://127.0.0.1:8000/`;
- Swagger: `http://127.0.0.1:8000/docs`;
- healthcheck: `http://127.0.0.1:8000/health`.

Проверить контейнеры и посмотреть журналы:

```bash
docker compose ps
docker compose logs -f api worker
```

Тестовую PostgreSQL при необходимости можно поднять отдельным профилем:

```bash
docker compose --profile test up -d test_db
```

Остановить сервис, сохранив базу и файлы:

```bash
docker compose down
```

Полностью удалить локальные данные можно явно командой `docker compose down -v`.
Для обработки DXF размером около 150 МБ выделите Docker Desktop не менее 4 ГБ
памяти: фактический пик worker на предоставленном примере составлял около 1,6 ГБ.

Контейнеры читают `.env`, но Compose автоматически заменяет адрес PostgreSQL на
`db`, путь файлового хранилища на `/data/storage`, а адрес API на `0.0.0.0:8000`.
Для локального OpenAI-compatible сервера на macOS используйте в `LLM_BASE_URL`
адрес `http://host.docker.internal:<порт>/v1` вместо `127.0.0.1`.

## Frontend

Интерфейс покрывает создание проекта, загрузку и анализ DXF, подтверждение
настроек, генерацию плана, OpenLayers-preview, ручные правки посадок, повторную
проверку и скачивание экспортного комплекта.

После анализа backend предлагает назначение слоёв с причиной и уровнем
уверенности. Форма позволяет искать и массово сопоставлять слои, скрывает
действительно неиспользуемые записи и отдельно показывает объекты внутри BLOCK.
Границу можно выбрать среди крупнейших замкнутых полилиний на локальной карте.
Все предложения требуют подтверждения при сохранении конфигурации.

Интерфейс запоминает ID открытого проекта и после обновления страницы восстанавливает
последний файл, анализ, конфигурацию и план из PostgreSQL. На первом шаге также можно
выбрать ранее созданный проект.

Для разработки запустите backend на `127.0.0.1:8000`, затем:

```bash
cd frontend
npm install
npm run dev
```

Vite откроет интерфейс по адресу `http://127.0.0.1:5173/static/` и проксирует
запросы `/api` в FastAPI.

Production-сборка проверяется командой:

```bash
cd frontend
npm run build
```

Сборка попадает в игнорируемый каталог `app/static`. Если этот каталог существует,
FastAPI раздаёт интерфейс через `/static/` и перенаправляет корневой маршрут `/` на
него.

## Большие DXF

По умолчанию принимаются исходники до 300 МБ, а результат экспорта — до 500 МБ.
Загрузка и публикация файлов выполняются потоково. Worker остаётся единственным и
последовательным; для каждого тяжёлого задания он журналирует размер исходника,
время выполнения и пиковый RSS процесса.

Preview ограничен 2 000 исходных объектов, 2 000 нормативных зон и общим бюджетом
около 200 000 координат. Геометрия карты может упрощаться с погрешностью от 0,1 м,
но расчёт, Validator и итоговый DXF используют исходную геометрию. Лимиты задаются
переменными `MAX_UPLOAD_SIZE_BYTES`, `MAX_ARTIFACT_SIZE_BYTES`,
`PREVIEW_SIMPLIFY_TOLERANCE_M`, `PREVIEW_MAX_OBJECTS`,
`PREVIEW_MAX_RESTRICTIONS` и `PREVIEW_MAX_COORDINATES`.

## LangChain-агент

Кнопка автопланирования вызывает `POST /api/projects/{project_id}/agent/autoplan`.
Python рассчитывает допустимые точки, расстояния до дорог, зданий и границы, а LLM
собирает из них аллеи, озеленение у зданий и группы кустарников. Python отбрасывает
некорректный выбор, дополняет композицию профильными точками и запускает независимый
Validator. Координаты и нормативы модель не придумывает.

По умолчанию агент отключён. Для OpenAI добавьте в `.env`:

```dotenv
AGENT_ENABLED=true
LLM_PROVIDER=openai
LLM_MODEL=<модель-с-поддержкой-tool-calling>
LLM_API_KEY=<ключ>
ALLOW_EXTERNAL_LLM=true
```

Для локального OpenAI-compatible сервера задайте `LLM_PROVIDER=openai_compatible`,
`LLM_BASE_URL=http://127.0.0.1:.../v1` и требуемый сервером `LLM_API_KEY`.
Loopback-подключение не требует `ALLOW_EXTERNAL_LLM=true`. После изменения `.env`
перезапустите FastAPI и worker: обращение к LLM выполняет worker.

## Sentry

Sentry собирает необработанные ошибки FastAPI, исключения worker и сообщения
Loguru уровня `WARNING` и выше. Интеграция отключена, пока в `.env` не указан DSN:

```dotenv
SENTRY_DSN=https://<public-key>@<host>/<project-id>
SENTRY_ENVIRONMENT=development
SENTRY_RELEASE=landscape-planner@1.0.0
SENTRY_ENABLE_LOGS=true
SENTRY_TRACES_SAMPLE_RATE=0.0
```

После изменения настроек перезапустите API и worker. Они помечаются в Sentry тегом
`service=api` или `service=worker`. Значение `SENTRY_TRACES_SAMPLE_RATE` находится
в диапазоне от `0` до `1`; значение `0` отключает performance-транзакции. Тела HTTP-
запросов, содержимое DXF и персональные данные приложением в Sentry не отправляются.

В итоговом DXF деревья и кустарники имеют разные символы и отдельные слои. Рядом
с каждой посадкой добавляется видимая подпись вида `Д-001 · Липа мелколистная` или
`К-001 · Сирень обыкновенная`; полные UUID, тип, порода и марка также сохраняются
в ATTRIB блока.
