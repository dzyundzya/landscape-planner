# Демонстрационный участок Автосада

[greenplan_demo.dxf](greenplan_demo.dxf) — синтетическая подоснова для показа цепочки
**загрузка → анализ → настройка → генерация → проверка → DXF и отчёт**.
Она содержит здание, дорогу, инженерные сети и существующие деревья. Это учебный
участок, а не объект пилота «20 улиц» и не эталон полного нормативного соответствия.

В комплект входят:

- [Исходный DXF](greenplan_demo.dxf), 38 852 байта.
- [Готовая конфигурация](greenplan_demo.config.json) для `PUT /api/projects/{id}/config`.
  Она задаёт область посадки **выше дороги**, классификацию слоёв и параметры
  для 12 деревьев и 20 кустарников.
- Эта инструкция для UI и Swagger.

Исходный файл не нужно генерировать скриптом — он уже находится в репозитории.
Название `greenplan_demo.dxf` и надпись Greenplan внутри чертежа сохранены от
первоначального демо; публичное название сервиса — «Автосад».

## Что находится в чертеже

Формат — **DXF R2010 (`AC1024`)**, единицы — **метры** (`$INSUNITS=6`).
Все координаты локальные, без географической привязки.

| Объект | Геометрия |
|---|---|
| Внешняя рамка | Прямоугольник `(0, 0)` — `(100, 60)`, площадь 6 000 м² |
| Здание | Прямоугольник `(10, 36)` — `(30, 52)`, площадь 320 м² |
| Края дороги | Две горизонтальные линии от `X=0` до `X=100`, на `Y=10` и `Y=18` |
| Водопровод | Ломаная `(5,27) → (40,27) → (58,32) → (95,32)` |
| Подземный электрокабель | Ломаная `(52,4) → (52,24) → (70,42) → (96,42)` |
| Существующие деревья | Окружности: центр `(39,46)`, радиус 2,5 м; `(48,50)`, 2 м; `(78,49)`, 3 м |
| Подписи | Пять текстовых объектов: название участка, здание, дорога и две сети |

В modelspace **14 сущностей**: 4 `LWPOLYLINE`, 2 `LINE`, 3 `CIRCLE`, 5 `TEXT`.
Всего 9 слоёв, включая пустые служебные `0` и `Defpoints`. Внешних ссылок XREF
и неподдерживаемых сущностей анализатор не обнаружил. Служебные определения
блоков присутствуют, вставок `INSERT` в modelspace нет.

## Почему область посадки меньше рамки

Дорога изображена двумя линиями, а не замкнутым площадным объектом. При назначении
им типа «Дорога» алгоритм строит отступы от каждого края, но **не восстанавливает
автоматически всю проезжую часть между ними**. Выбор всей рамки 6 000 м² может
оставить допустимые точки внутри дорожной полосы.

Для этого демо используйте верхнюю часть участка:

| Поле границы в UI | Значение |
|---|---:|
| `min X` | 0 |
| `min Y` | 18 |
| `max X` | 100 |
| `max Y` | 60 |

Площадь области расчёта — **4 200 м²**. Дорога остаётся в исходном чертеже,
её края продолжают участвовать в расчёте отступов. Эта граница уже записана
в готовом JSON-конфиге. Это явный выбор области проектирования, а не изменение DXF.
Не выбирайте вместо неё контур здания площадью 320 м².

## Сопоставление слоёв

Единица: **метр**. Тип территории для примера: **дворовая территория** (`courtyard`).
Это сценарная настройка синтетического участка, не классификация реального объекта.

| Слой | Тип в UI / API | Роль | Атрибуты |
|---|---|---|---|
| `0`, `Defpoints` | Не учитывать / `ignore` | Линия | — |
| `РАМКА_ГРАНИЦА_УЧАСТКА` | Не учитывать / `ignore` | Линия | Граница задаётся отдельно |
| `ЗДАНИЕ` | Здание / `building` | Площадной объект / `area` | `measurement_reference=exterior_wall`, `building_use=other` |
| `КРАЙ_ДОРОГИ` | Дорога / `road` | Линия / `line` | `measurement_reference=roadway_edge` |
| `ВОДОПРОВОД` | Водопровод / `utility_water` | Линия / `line` | `measurement_reference=utility_outer_surface` |
| `ЭЛЕКТРОКАБЕЛЬ` | Электросеть / `utility_power` | Линия / `line` | `measurement_reference=utility_outer_surface`, `network_kind=underground_power_cable` |
| `СУЩЕСТВУЮЩИЕ_ДЕРЕВЬЯ` | Существующее дерево / `existing_tree` | Площадной объект / `area` | — |
| `ПОДПИСИ` | Не учитывать / `ignore` | Линия | Текст не участвует в расчёте |

Для JSON роль указывается в `attributes.geometry_role`. UI заполняет часть
атрибутов по выбранному типу; проверьте назначения перед сохранением. Нельзя
назначить все слои в `ignore`: тогда расчёт потеряет препятствия и сети.

В рамках этого синтетического сценария линии сетей интерпретируются как наружная
поверхность коммуникаций, а окружности деревьев — как занятые площадные объекты.
Для реального DXF эти допущения нужно подтверждать отдельно. Существующие деревья
учитываются с заданными проектными интервалами, а не удаляются из подосновы.

## Параметры генерации

| Параметр API | Значение |
|---|---:|
| `max_trees` | 12 |
| `max_bushes` | 20 |
| `tree_tree_distance_m` | 5 |
| `bush_bush_distance_m` | 1,5 |
| `tree_bush_distance_m` | 2,5 |
| `grid_spacing_m` | 1 |

В JSON дробная часть записана через точку. Интервалы — параметры демонстрационного
проекта, они не заменяют нормативные расстояния до зданий и коммуникаций.
В алгоритмическом режиме количества являются верхними лимитами: при других
входах алгоритм может разместить меньше растений.

## Запуск через интерфейс

1. Запустите приложение по [основному README](../README.md).
2. Создайте новый проект «Автосад — демо» и загрузите `greenplan_demo.dxf`.
3. Запустите анализ. Для текущего файла ожидаются 14 сущностей, 5 подписей
   и два кандидата границы: 6 000 м² и 320 м².
4. Выберите метры и дворовую территорию. В полях границы задайте
   `min X=0`, `min Y=18`, `max X=100`, `max Y=60`.
5. Проверьте слои по таблице выше и задайте параметры 12/20 и интервалы.
6. Сохраните конфигурацию. Кнопка «Помощник по озеленению» требует настроенного
   LLM. При настройках по умолчанию используйте алгоритмический запуск ниже.
7. После успешной генерации откройте план, выберите посадку и проверьте объяснение.
8. Сформируйте экспорт. Скачайте DXF, JSON-план и оба отчёта одной ревизии.

## Воспроизводимый запуск без LLM через Swagger

Откройте [Swagger](http://127.0.0.1:8000/docs). Все пути ниже включают стандартный
префикс `/api`. Используйте ID, возвращённые вашим сервером, а не фиксированные числа.

1. `POST /api/projects/`: создайте проект с именем «Автосад — демо» по схеме Swagger.
2. `POST /api/projects/{id}/files/`: загрузите DXF как файл формы.
3. `POST /api/projects/{id}/analyze`: получите задачу. Опрашивайте
   `GET /api/jobs/{job_id}` до `succeeded`; при `failed` прочитайте ошибку.
4. `PUT /api/projects/{id}/config`: вставьте **полное содержимое**
   [greenplan_demo.config.json](greenplan_demo.config.json) в тело запроса.
   Загружать JSON в поле загрузки DXF не нужно. Сервер сам фиксирует версии
   справочников; файл не содержит ID проекта, секретов или поддельных статусов проверки.
5. `POST /api/projects/{id}/plans`: запустите расчёт без тела запроса и дождитесь
   `succeeded` у возвращённой задачи. Сохраните `plan_id` из результата.
6. `GET /api/projects/{id}/plans/{plan_id}`: получите план и заголовок `ETag`.
   В `GET /api/projects/{id}/plans/{plan_id}/report` изучите проверки.
7. Для экспорта вызовите `POST /api/projects/{id}/plans/{plan_id}/exports`, передав
   текущий `ETag` в заголовке `If-Match`, например `"1"`. Дождитесь завершения
   экспортной задачи и получите комплект по возвращённому ID экспорта.
8. Скачайте артефакты по их URL. После API-генерации можно открыть проект в UI
   или обновить его страницу для просмотра текущего плана.

При ручных правках получите новую ревизию и выполните `/validate` с её `If-Match`
перед экспортом. Обычный экспорт доступен только при разрешающих статусах плана
и Validator. `?draft=true` используйте лишь как явный запрос демонстрационного
черновика при `needs_verification`; геометрические нарушения блокируют любой экспорт.

## Что показать в результате

- Посадки находятся выше дороги и внутри выбранной области.
- Здание, сети и существующие деревья присутствуют в исходных слоях.
- У выбранной посадки есть проверки расстояний с фактическими значениями,
  требованиями, документом и пунктом. Объяснение LLM не заменяет эти проверки.
- В CAD можно независимо отключить `GREENPLAN_TREES`, `GREENPLAN_BUSHES`
  и слои подписей, оставив исходную подоснову.
- Рядом с посадками показаны короткие марки `Д-001`, `К-001`; породы вынесены
  в экспликацию `GREENPLAN_LEGEND`. Расчётные зоны по умолчанию выключены.
- Комплект содержит `result.dxf`, `plan.json`, `report.json`, `report.md`.
  У чернового комплекта есть префикс `draft-` и предупреждения.
